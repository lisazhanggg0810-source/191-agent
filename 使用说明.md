# CRC-LNM MCP Usage Guide

## Supported Workflow

The service accepts only allowlisted, deidentified case references backed by
precomputed 1409-dimensional CT features, 768-dimensional pathology features, and
the required clinical fields. Raw imaging, file paths, and caller-supplied feature
vectors are not MCP inputs.

The local development configuration at `configs/mcp.local.yaml` converts the trusted
release JSONL into a verified local case cache on first startup. This configuration is
for repository development and is not a ModelScope hosted STDIO configuration.

## Local Development

Run from the repository root after installing the project dependencies:

```text
crc-lnm-mcp --config configs/mcp.local.yaml --transport stdio
```

For the HTTP container path, use `configs/mcp.yaml`, set
`CRC_LNM_MCP_BEARER_TOKEN`, and connect to `/mcp` on port 8000.

## ModelScope Hosted STDIO

Publish the wheel to PyPI first. The ModelScope server configuration must be the exact
JSON in `configs/modelscope-mcp.json`, whose first server uses:

```text
uvx crc-lnm-medical-agent@latest --transport stdio
```

The published wheel contains the immutable deployment bundle and trusted release JSONL.
It builds its case cache and artifacts automatically under the system temporary directory
unless `CRC_LNM_MCP_RUNTIME_ROOT` is supplied by the operator. It never needs a repository
path, local package path, or caller-provided startup argument.

After ModelScope passes `list_tools`, manually test each required tool. Then obtain the
service URL, add it to Nexent, enable the six tools, debug the agent, publish it, and
verify a post-publication question in the target environment.
